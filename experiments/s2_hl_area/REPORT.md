# S2-6c：高光约束修正（裁切面积）与 fit_config_v1 冻结

参考图拟合器是研究工具（看得到参考图），用于生成一致的参数标签和检验表达能力，不是自动校色基线。
ΔE2000 是相对参考图的差异，不是颜色准确度。

## 问题（S2-6b）

原高光约束按“超出白点几档”平滑计罚，大片区域只略微越线时几乎不罚。shop_r01 的 DSC_3825 天空在
λ=0.05、权重 30 下仍有 7.9% 被截白，云层层次丢失。

## 修正：两层高光保护

1. **新增裁切面积（加入目标函数）**：`fit.clip_area`。逐通道：白点以下为 0，越过白点后在 0.05 档内按 smoothstep
   升到 1；一个像素计 1 − ∏(1 − r_c)；参考图本身已裁切的通道不计。按图像平均，权重 `area_weight`
   （单位：ΔE / 全图比例）。白点以下的像素不罚，避免与参考图中本来就接近白色的高光冲突。
2. **高光局部层次（只作诊断）**：`compare.highlight_texture`。在参考图高光区（L* ≥ 80，参考图未裁切，
   且 5×5 窗口整个落在该区域内）比较 |L* − 局部均值| 的平均值，给出“我们 / 参考”的比值。
   能发现“没有越线、但高光被压平”的情况。窗口必须整体落在高光区内，否则天空和山的交界会主导这个指标（单元测试发现并修正）。

### DSC_3825 目视核对

天空裁切对比图（默认 | 面积 0 | 面积 10 | 店家），`experiments/s2_hl_area/DSC_3825_sky.jpg`（不进 git）：

- 面积 0：天空几乎是一片平的米白。
- 面积 10：淡淡的云层明暗重新出现，比面积 0 明显，比店家略弱。
- 店家图本身也大幅压缩了天空，默认输出的云层反而最明显。所以层次比值 1 的意思是“和店家一样淡”，不是“恢复原有云层”。
- 另一个明显差异是颜色：我们的天空偏米黄，店家偏冷白。这属于高光区的白平衡 / 色彩，不归高光约束管，记为已知问题。

### 第二层是否加入目标函数：不加

- 加了面积约束后，层次比值低于 0.85 的只剩 DSC_3825（0.76），它剩下的差距有一部分来自店家自己的压缩。
- 这个比值没有统一的目标：NLP 上中位数约 1.5（NLP 的高光比我们更平滑），店家约 1.0。拿它当拟合目标会把某一家的
  平滑或锐化风格当成要求。它适合用来发现“被压平”（比值明显低于 1），所以只保留为诊断，每次拟合都记录。
- 另外，目标函数现在用的是抽样后的一维像素，加入局部层次项需要改成二维计算，复杂度增加，而这组数据上看不到收益。

## 冻结：fit_config_v1

按 GPT 给出的条件逐项核对：3825 不再大面积人为裁切、层次部分恢复（目视确认）；NLP 上已解决的问题未复发；
整体误差没有变差；多起点仍稳定；没有新增极端参数（碰边界次数不变，参数变化最大 0.30 个尺度单位）。

冻结内容（`src/filmcolor/fit.py` 的 `FIT_CONFIG_V1`，入口 `fit_reference_v1`）：

| 项 | 值 |
|---|---|
| 模式 | 7reg（7 个逐张参数） |
| 目标函数 | 平均伪 Huber(ΔE2000，δ=1) + 30 × 深度惩罚（δ=0.05 档）+ 10 × 裁切面积（0.05 档内升满）+ 0.05 × Σ((θ − 默认) / 尺度)² |
| 参数尺度 | ev 1.0，temp / tint / sat / contrast / shoulder 0.25，midtone 0.05 |
| 参数边界 | ev ±3，temp / tint ±1，sat 0～2，contrast 0.5～2，midtone 0.05～0.5，shoulder 0～1 |
| 参考图已裁切阈值 | 我们的编码下 ≥ 0.99 |
| 优化 | L-BFGS-B，5 个固定起点（种子 0），每次抽 20000 像素，有限差分步长 0.002，每起点最多 300 次迭代 |
| 代码版本 | 引入 `FIT_CONFIG_V1` 的提交（`git log -S FIT_CONFIG_V1`） |

`fit_reference_v1` 运行前核对模块中的尺度、边界和各常量与冻结值一致，不一致（例如在 `experimental_bounds` 内）就报错。
`fit_reference` 的默认参数没有改动，以前的实验仍可复现。

**说明**：冻结是为了让后续实验使用同一套参数定义，不代表这组超参数已被证明最优；不同配置生成的参数标签不能混用。
