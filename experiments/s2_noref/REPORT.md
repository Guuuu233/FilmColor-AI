# S2-7 无参考自动校色：noref_v1、global_look_v1 与 noref_v2 逐组消融

**全部成绩都是开发集成绩**（NLP 12 张 + shop_r01 21 帧，`data/manifests/SOURCES.md`），不是独立测试成绩。汇总中位数排除 DSC_3822 和 DSC_3858 两张异常帧（S2-6b 事先定的规则），这两张单独报告。ΔE2000 是相对参考图（NLP 默认转换 / 店家修图）的差异，不是颜色准确度。

## 1. 结论

1. **固定观感就是目前最好的无参考方案。** 一套在开发参考上拟合出来的固定 7 参数（`global_look_v1`），把差异从默认的 11.9 / 12.5 降到 6.4 / 6.7（NLP / 店家）；在一套参考上拟合、拿到另一套上评估，也能做到 7.40 / 6.91。
2. **按事先定的规则，四组逐张调整没有一组被保留**（亮度、白平衡、影调、饱和度）。所以 noref_v2 = 固定观感 + 输入质量检测，不做逐张调整。
3. **逐张调整的提升空间是真实存在的，而且集中在亮度和白平衡。** 逐组上限分析（看过参考图，只作诊断）表明，七个参数全开能做到 3.6 / 3.5；单组收益最大的帧数，亮度 19 帧、白平衡 13 帧，影调 0 帧。但现有输入统计和这些需要的调整几乎不相关（秩相关 +0.27、+0.19、+0.04，均不显著）。**统计量抓不到画面内容**，例如分不清“逆光、主体太暗”和“本来就是低调”。这就是以后学习模型要解决的问题。
4. **异常帧**：3822、3858 都被标为 `manual_review_required`，参数停在固定观感、不做增强。但 3858 的反转错误本身没有修（`docs/ENGINE_MATH.md` 已知限制第 4 条）。

## 2. 实验性质与信息边界

- **推理时**：估计器只读这一帧的正片，店家那卷另外读同卷其他帧的统计，再加上冻结的配置。`estimate_params_v2` 没有参考图参数，`noref.py` 不导入拟合或对照模块（`tests/test_noref.py::test_information_isolation`）。
- **开发时**：`global_look_v1` 是用开发参考拟合出来的（监督来源），作为独立配置保存（`src/filmcolor/configs/global_look_v1.json`，含来源与局限说明），**没有写进引擎默认值**。默认输出仍与 Sprint 1 逐字节一致（`test_default_render_reproduces_sprint1_output_bytes`）。
- 逐组上限分析看过参考图，**只用于失败归因**，结果不进入任何估计器。

## 3. noref_v1（设计草案的逐张启发式，`dev0/`）

| | NLP | 店家 |
|---|---|---|
| 默认参数 | 11.89 | 12.51 |
| noref_v1 | 11.62 | 11.73（21 帧中 18 帧好于默认） |
| v1 上限（看过参考图） | 3.85 | 3.79 |

几乎没有效果，部分帧更差：9239 从 5.6 到 10.9，8434 从 12.9 到 15.2，黑白片 9228 从 6.9 到 10.1。原因是它的基础常数（饱和度 1.2、中间调 0.18、反差从 1 起调）离两套参考的观感都很远。noref_v1 的代码保持不动，`dev0` 可以复现。

## 4. global_look_v1（`scripts/noref_global.py` → `global_look.json`）

| 拟合用的数据 | 在 NLP 上评估 | 在店家上评估 |
|---|---|---|
| 只用 NLP | 6.45 | **7.40**（跨集） |
| 只用店家 | **6.91**（跨集） | 6.39 |
| 两者合并（= global_look_v1） | 6.37 | 6.66 |

参数（两者合并）：ev −0.05，temp −0.24，tint +0.18，sat 1.10，contrast 2.00（上界），midtone 0.27，shoulder 0.11。

局限：
- 反差在每次拟合中都顶到上界 2.0，按此前决定没有放宽范围。
- 高光压缩在两套参考之间差别很大（只用 NLP 拟合 0.90，只用店家 0.08），是风格差异；合并值跟随店家那卷。
- 每帧等权，店家 21 帧压过 NLP 12 帧。
- 只来自两套翻拍设备（富士 X-T2 X-Trans、尼康 Z 7II Bayer），可能含有设备偏差，不能当作通用观感。

## 5. 逐组消融（`scripts/noref_ablation.py` → `v2_ablation/ablation.json`）

**保留规则（运行前定，写在脚本里由程序判定）**：和上一个保留阶段相比，需要同时满足：(1) 两套的中位数都下降；(2) 两套合计，变好超过 0.5 的帧数多于变差超过 0.5 的帧数；(3) 新增裁切最大值不超过 2%。不通过的组保持固定观感的值。

| 阶段 | 逐张调整的组 | NLP | 店家 | 变好 / 变差 | 新增裁切最大值 | 保留 |
|---|---|---|---|---|---|---|
| A | 无（只用观感） | 6.37 | 6.66 | - | 0.5% | 是 |
| B1 | 亮度（对称区间） | 8.06 | 6.66 | 4 / 7 | 2.1% | 否 |
| B2 | 亮度（只提亮，不压高调） | 8.06 | 6.66 | 4 / 2 | 2.1% | 否 |
| C | 白平衡 | 7.39 | 7.48 | 3 / 15 | 1.0% | 否 |
| D | 影调（高光压缩、反差） | 6.37 | 6.65 | 1 / 1 | 0.5% | 否 |
| E | 饱和度 | 6.37 | 6.70 | 0 / 0 | 0.5% | 否 |

D 的编码亮度跨度区间取 A 阶段 47 帧（两套全部 ok 帧，不看参考）跨度的 p10～p90 = [0.59, 0.88]。

**逐组失败原因：**
- **亮度**：8983（逆光）从 24.0 降到 9.9，9237、3853 也各好约 2；但 9235（4.1→9.4）和 9239（6.0→14.9）被提亮后严重变差。这几张的输入统计几乎相同（中位数 0.04～0.07，p99 0.76～0.90），全局直方图分不出逆光和低调。
- **白平衡**：两个问题叠加。
  - 店家那卷每帧都加了整卷估计的 tint +0.12，而观感的 tint +0.18 已经包含了这卷的平均偏色，**重复校正**。
  - 更根本的是，“把低饱和像素拉回中性”解释不了调色师逐张的选择：参考需要的 temp 偏移在 −0.29～+0.42（p10～p90），估计器给出的接近 0。黑白片 9228 是例外：估计器给出 tint +0.108，上限是 +0.10，单看估计是对的，错在叠加到观感上。
- **影调**：观感的反差已经在上界，只能往下调；区间外的帧很少。
- **饱和度**：观感的饱和度只有 1.10，按色彩丰富程度往下调的幅度很小。

## 6. 失败归因：逐组上限（`scripts/noref_group_oracle.py` → `group_oracle.json`，看过参考图，只作诊断）

其他参数固定在观感值，只让一组参数逐张对着参考拟合（目标函数同 `fit_config_v1`、不加正则，3 个起点）：

| | 观感 | 只调亮度 | 只调白平衡 | 只调影调 | 只调饱和度 | 七个全开 |
|---|---|---|---|---|---|---|
| NLP（12） | 6.37 | 5.93 | 5.78 | 7.07 | 5.78 | 3.63 |
| 店家（21） | 6.66 | 5.26 | 5.43 | 6.39 | 6.64 | 3.53 |

- 单组收益最大的帧数：亮度 19、白平衡 13、饱和度 1、影调 0。
- 各组之间有明显协同：单组收益之和远小于七个全开。
- “只调影调”在 NLP 上的中位数反而比观感高：目标函数优化的是平均伪 Huber 加高光惩罚，不是中位数。
- 3858 只要亮度调对（ev 约 −2），就能降到 2.3，说明它的问题在白点和黑点。

估计器有没有看到上限需要的调整（`scripts/summarize_noref_v2.py`）：

| 量 | 上限需要的调整 p10～p90 | 秩相关（需要, 估计） |
|---|---|---|
| 中位像素亮度（档，B2） | −0.44～+0.73 | +0.27（p = 0.13） |
| temp（C） | −0.29～+0.42 | +0.19（p = 0.29） |
| tint（C） | −0.12～+0.14 | +0.04（p = 0.84） |

需要的调整都以 0 为中心，说明观感的中心是对的；逐张偏移现有统计量几乎预测不出来。

## 7. 目视核对（`v2_previews/`，图像不进 git）

每行：默认 | 固定观感 | v1 上限 | 参考。
- **固定观感整体有效**：默认的黄绿偏色基本消掉，天空恢复中性或蓝色，多数帧接近参考。
- **暖光场景被校冷**：3827（阳光照着的山）参考保留金黄色调，观感把它校成冷灰，ΔE 23；上限需要的 temp 是 +0.79。和 GPT 担心的“特殊光照被强行中性化”是同一类问题，只是这次是**固定观感**造成的，不是逐张估计。3828 也有同样的倾向。
- 几张蓝天比店家淡，饱和度偏低。
- 逆光的 8983 在观感下整张太暗（亮度组的失败案例）。
- 3822、3858 处理错误，被标为需人工检查是对的。

## 8. 输入质量检测与置信度

- **低信息**（色调范围 < 3 档）或**白点失效**（p99 高出反转白点超过 1 档）时，返回 `manual_review_required`，参数停在观感。开发集里只命中 3822（色调范围 2.12 档）和 3858（p99 高出 2.06 档）。不命中的帧中，p99 最高只高出白点 0.74 档（3830），余量 0.26 档，**只有一个样本支撑这个阈值**。
- 管线（`convert.py --auto`）只统计中心区域，3858 改为由“低信息”（2.53 档）拦下。两条路径都能拦住，但判据依赖统计区域。
- **曝光置信度**：v1 只看“高于白点的比例”，开发集上几乎恒为 1，等于没有区分能力。v2 乘上一个随调整幅度增大而下降的因子（1～2.5 档）。在 B1 上检验：置信度 < 1 的 3 帧，亮度误差中位数 0.55 档；置信度 = 1 的 30 帧是 0.26 档；秩相关 −0.28（p = 0.11）。**方向对，但证据弱**，样本太少。
- **白平衡置信度接近 0 时 tint 仍是 +0.12**：单张估计权重为 0，剩下的部分由整卷估计按一致性加权补上（`target += (1 − conf) · roll_conf · centre`）。店家那卷各帧一致，整卷估计被完整采用；NLP 不传整卷信息，所以偏移接近 0。

## 10. 对后续的含义

- 无参考的确定性算法，目前能做到的就是“固定观感 + 质量检测”。要再往下降，得逐张判断**亮度**和**白平衡**，而判断依据在画面内容里（逆光还是低调、暖光是不是场景本身的颜色），不在全局统计里。这是学习模型要解决的具体问题，也是它必须超过的基线：开发集上 6.4 / 6.7。
- `global_look_v1` 只来自两套设备，换翻拍设备或光源可能失效。下一步最有价值的是**不同设备、不同胶卷的新数据**，先用当前算法跑一遍、记录失败，再决定要不要按设备做校准配置。
- 3858 这类画格需要在反转阶段修（独立黑点或检测大片均匀区域），不能指望校色参数去掩盖。
