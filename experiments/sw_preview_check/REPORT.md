# 预览与导出的接近程度（软件里程碑 SW-M1 的补充验收，2026-10-19）

脚本：`scripts/preview_check.py`，数据在 `results.json`。全部用开发集文件，经冻结保护检查。

## 两项保证要分开看

1. **导出 = 直接转换，逐字节相同。** 由 `tests/test_preview.py` 用钉死的输出哈希检验。覆盖的路径：扫描仪彩色、扫描仪黑白、相机默认、相机给定参数、相机 `--auto`，以及改用手动片基重新载入（`reload`）。
2. **预览接近“导出后按同样倍数缩小”的结果。** 这只是近似，下面是实测。

## 误差的定义

- 误差 = |预览渲染 − 全分辨率渲染按预览倍数块平均|，逐像素、逐通道计算。
- 取值是 sRGB 编码后的显示值，范围 0～1，即写进 TIFF 之前的值。
- 全分辨率渲染走导出用的同一条路径：`pipeline.positive` + `render.render`。
- 区域在缩小后的参照图上划分：
  - 暗部：明度 < 0.1；
  - 亮部：明度 > 0.9；
  - 高饱和：最大通道减最小通道 > 0.4；
  - 强边缘：明度梯度最大的 5%；
  - 裁切：这一块里至少有一个全分辨率像素到了输出白。

## 结果：全图平均 / 99 百分位

| 文件（预览尺寸） | 默认 | 中等参数 | 极亮、硬反差 | 极暗、软反差 | 强偏色、高饱和 |
|---|---|---|---|---|---|
| `_DSF8948.RAF`（富士 X-Trans，1508×1008） | 0.0011 / 0.017 | 0.0019 / 0.025 | 0.0070 / 0.173 | 0.0006 / 0.014 | **0.028 / 0.47** |
| `A126.NEF`（Z7 II，自有开发卷） | 0.0024 / 0.018 | 0.0038 / 0.039 | 0.0086 / 0.094 | 0.0002 / 0.002 | 0.0020 / 0.017 |
| `19941217A-08-tokyo.dng`（BlueNeg 扫描仪） | 0.0008 / 0.005 | 0.0013 / 0.009 | 0.0025 / 0.030 | 0.0003 / 0.002 | 0.0046 / 0.045 |

- **最大的误差出现在强边缘和高饱和区域。** RAF 在默认参数下，边缘区的 99 百分位已经有 0.18；在“强偏色、高饱和”参数下，高饱和区占 73% 的像素，99 百分位 0.5，边缘区 0.56。
- **误差的来源**：误差值都是 1/16 的整数倍（缩小倍数 4，每块 16 个像素）。说明全分辨率下，一部分带噪点的像素在单个通道上被裁到了 0 或 1。预览先平均、后渲染，把这些裁切噪点平均掉了，所以在饱和或噪点多的地方，预览会低估裁切斑点。X-Trans 的 RAF 噪点最大，所以最明显。
- **调参数后重新渲染的时间**：0.08～0.11 秒（RAF，1508×1008）。

## 对界面的要求

- 预览要标明“缩小预览，近似”。
- 需要提供 **1:1 局部预览**：对用户选的局部区域做全分辨率渲染，用来检查饱和和裁切。
- 只调 7 个渲染参数时才能复用缓存。换片基、改画面区域、改白点、切换胶片模式、重新估计自动参数，都要调用 `Preview.reload` 重新解码和反转；`load_kwargs` 里记录了当前用的是哪些参数。

## 局限

只测了 3 张图、5 组参数，不代表所有机型和场景。
