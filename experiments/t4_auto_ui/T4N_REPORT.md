# T4n 底层稳健性修复（2026-10-30 任务单）

四项机制已按任务单实现，五个设备样本完成最终源码探测，完整单元测试 **361 项通过**，185 帧开发集及 123 帧 BlueNeg 检查集已完成全量核验。**未达到任务单全部验收预期**：开发集出现 A104 +.517890、A138 +.177167 两帧退步，检查集目标 199807B-08 未恢复。作为可复现 T4n 实现记录交付，不标为零退步定版。基线为 T4m `13db565`，工作分支 `t4n`；保持指定参数，不根据这些结果追加调阈值。用户既有 `paths.py` 修改保持原样、不提交。

## 修改范围

- 自动片基：仅在中位数共识为空时使用候选二维邻居最多的实际点作为种子；高密度假片基按全部通道 p98 > 2.2 倍、且 >25% 有效块全部通道更亮的条件触发一次 .25 均匀度回退。`mode_seed=True` 表示本次估计任一阶段曾使用种子（包括后续被放宽重估替代的初始阶段），不表示最终候选必定使用种子。
- 反演：指数在 12 处封顶，防止极小通道白点导致 float32 幂上溢。普通密度像素按原公式输出。
- 蓝白点护栏：B/G 密度比 < .55 时返回 below_valid_ratio，不抬升。
- 青偏置信度：增加中灰区自身 log2 R/G < -.65 的条件。
- App 扫描缓存键与缩略图版本更新为 t4n，确保旧片基失败与假片基缓存不遮蔽修复。
