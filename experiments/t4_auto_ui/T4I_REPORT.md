## 改动

1. **白平衡（`noref.estimate_wb_v3`）**：上下半幅色度差 `top_bottom_spread` 的计算移到前面。只有上下半幅分离 ≥ 0.10，且上半幅更蓝（B/G 高 ≥ 0.05）或更青（R/G 低 ≥ 0.05）时，才算晴空场景，才做 T4f 的亮区降权和 T4h 的灰世界蓝轴降权。非晴空场景下，如果灰世界色偏模长 ≥ 0.20，灰世界权重改为 0.60，置信度下限 0.80。`wb_v3_strength` 0.65 → 0.80。开关为 `wb_v3_sky_split_check`，关掉即回到 T4h。
2. **自动色阶（任务单 2.1 方案 A，驱动现有滑条，不新增 RenderParams 字段）**，都叠加在预设基值上：
   - 斜率：取有效像素（max > 0.003）各通道 2% / 98% 分位，若 R/G 或 B/G 在两端差 ≥ 0.10，按 G 的对数跨度换算成该通道的 gamma 补偿，限幅 ±0.08，写进 `slope_r` / `slope_b`。
   - 反差：编码亮度 p90 − p10 < 0.42 时，反差加 1.3 × 差额，最多加 0.22。系数 1.3 是我定的，任务单只给了“按比例”、阈值和上限。
   - 黑位：编码 p2 > 0.06 时，`blacks` 加 −clip((p2 − 0.05) × 1.1, 0, 0.28)，公式照任务单。
   - 开关分别为 `auto_slope` / `auto_contrast` / `auto_blacks`。
3. **片夹边框（`preview.holder_mask`）**：把两个通道超过 2 倍白点、最亮通道超过 16 倍、并且与画面边缘相连的像素判为片夹，预览和缩略图里显示为深灰 0.02。导出、1:1 裁切和所有估计都不受影响。`/api/open` 新增 `film_box`；直方图只统计 `film_box` 以内的像素。
4. **多卷合集（`app._exif_info` / `mixed_rolls`）**：`shutil.which` 找不到 exiftool 时，再试 `/opt/homebrew/bin` 和 `/usr/local/bin`，同时读取机身型号和拍摄日期。一个文件夹里机身或日期不止一组时判为合集：不标红，不自动切到 `roll_nat`，缩略图用各帧自己的片基，界面提示“此文件夹含多卷”。整卷模式仍可以手动选。

## 与任务单不一致、需要说明的事实

- **`_DSF8948` 两侧不是“饱和背光灯箱”。** 实测 RAW 两侧 10% 宽的列，RGB 中位约 0.005 / 0.009 / 0.005，片基是 0.88 / 0.78 / 0.26，D ≈ 2.0～2.3，饱和像素 0%。这是**不透明片夹**，不是透光区。反转后正片 R 约为白点的 300 倍、G 约 36 倍、B 约 3.6 倍，白点截断后就成了荧光黄或品红。任务单的三个判据（饱和掩膜、T ≥ 0.92 × 片基、D ≤ 0.035）在这张图上命中 0 个像素，所以改用上面第 3 条的判据。`_DSF8434` 也是同样情况（R 约 4400 倍）。
- **研究方的“逐通道自动色阶”收益没有复现。** 按任务单描述（1% 黑点、99.2% 白点、80% 逐通道加 20% 共享亮度，加在显示图上）做了 `levels_display` 变体，以 T4h 为基础：NLP 8.69 → 8.20（6 好 / 5 差），店扫 7.41 → 8.44，自有 8.81 → 10.38，全部 9.39 → 10.69（63 好 / 112 差）。自有卷上有极端退步，A021 14.52 → 41.57，A013 6.39 → 12.48。任务单报的基线（NLP 9.26、店扫 9.43、自有 25 帧 10.39）与本仓库 T4h 的数字（8.69、7.41）也对不上，帧集或协议应该不同，无法逐项核对。
- **`_DSF8948` 的目标值**：Temp 达到 +50，但这是 `wb_max_shift` 0.50 的上限，不是估计值自然落在 +40～+50。反差 1.52，在 1.45～1.52 内。blacks 是 −28，任务单期望 −8～−12；按任务单自己的公式，p2 = 0.325 时算出 −0.30，被 −0.28 截住。
- **`_DSF8948` 的改善几乎全部来自白平衡。** 只改白平衡（`no_auto_levels`）ΔE 是 8.17，再加自动色阶反而到 8.91。只加自动色阶（`wb_t4h`）是 12.14，比 T4h 的 11.12 还差。
- 截图里“已标出 11 帧异常”已经复现：PATH 里只有 Homebrew 的情况下，用户的服务读到了快门，片基却取自 `_DSF9228`，11 帧标红。PATH 里没有 Homebrew 时，12 帧曝光全是 1.0，片基取自 `_DSF8948`，标红 2 帧。现在两种情况都识别为 4 组合集（同为 X-T2，4 个拍摄日期），标红 0 帧。

## 建议（供研究方裁定）

1. **片夹显示**与**多卷合集识别**是独立的工程修复，有直接证据，建议采用。
