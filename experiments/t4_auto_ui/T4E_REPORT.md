## 1. 结论与待定事项

1. **标准预设回到 T4c 的位置。** NLP 11 帧：ΔE 中位 9.27（T4c 9.11、T4d 10.00），亮度差中位 −0.38 L\*（T4c −0.37）。
   185 帧合计：ΔE 中位 10.44（T4c 10.94），均值 12.04（T4c 12.08），但逐帧 40 帧变好、55 帧变差（|变化| > 0.25），
   所以整体可以看成和 T4c 持平，不是明确改进；中位数下降主要来自分布形状。
2. **逆光触发面收回。** 标准预设 26 / 185 帧权重 > 0（其中 8 帧为 1）；T4d 为 66（40），T4c 硬阈值为 21。
3. **逆光帧上五个预设的反差已经分开**（A012：1.28 / 1.37 / 1.42 / 1.52 / 1.57，T4d 全是 1.55）。
   **中灰并不总是分开**：标准和自然的 `base_midtone` 在 T4e 表里都是 0.23，两者在非逆光帧上中灰相同（按设计）；
   在暗到两者都碰到上限的逆光帧上也相同（A023：都是 0.32）。A012 上五个中灰是 0.30 / 0.30 / 0.32 / 0.33 / 0.36
   （自然 0.3022、经典印相 0.3000，只差 0.002）。如果要求"中灰严格区分"，需要研究方给自然一个不同的 `base_midtone`。
4. **预设切换** 46 MP 帧经 HTTP 实测中位 0.28 s（A012）/ 0.31 s（A023），各 10 次；T4d 为 0.73 s。剩下的基本都是估计器
   本身（多轮二分渲染，约 0.25 s）。任务单"< 0.15 s"那一句达不到，验收条目里的"~0.25 s"基本达到。
5. **自然预设在店扫上明显变差**（shop ΔE 中位 7.83 → 9.07，2 好 16 差；整体 40 好 106 差）。T4e 把自然的亮度带
   从 0.47–0.54 收到和标准一样的 0.45–0.52，同时反差 1.18、饱和度 0.95，比标准更灰更平。是否保留，请研究方看第 2 节。

## 4. 代码改动（`bf445cf`）

- `noref.py` NOREF_V3（rev `t4e-2026-10-25`）：标准 = 亮度带 0.45–0.52、中灰 0.23、反差 1.30、肩部 0.20、饱和度 1.02、
  保色 0.35、相机矩阵 0.35；`wb_prior_weight` 保持 0。四个预设按 T4e 表；人像保留 T4d 的 `backlit_p25_target = 0.34`
  （T4e 表没列这一项）。
- 逆光权重 w = ramp(p90; 0.78, 0.84) × ramp(0.32 − p25; 0, 0.06)（去掉 `backlit_span`）；反差 = min(1.65, 预设基线 + w × 0.12)，
  肩部 = min(0.55, 预设基线 + w × 0.15)，中灰向"使 p25 达 0.28 的中灰"移动 w，搜索上限 min(0.38, 预设基线 + 0.09)。
- `preview.py`：`Preview.est_input` 保存全分辨率正片的 `estimation_input`（4×4 块均值与掩膜，46 MP 帧约 35 MB），
  `with_auto` 直接复用。
- `app.py`：`THUMB_REV = "t4e"`。`index.html`：中灰滑条 UI 0 = 0.23（左 −0.13，右 +0.22），相机矩阵 / 保色默认 35。
- 测试：T4c 逆光测试和 T4d 连续权重测试改用"半边天空 + 暗前景"合成场景（T4d 用的 4–7 档对数均匀场景已达不到收窄后的
  权重）；新增"逆光帧上五预设反差与中灰各不相同"和"with_auto 复用缓存输入且与重新加载结果一致"两项。
