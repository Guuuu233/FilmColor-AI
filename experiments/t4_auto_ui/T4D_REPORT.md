## 1. 需要研究方确认的事

1. **任务单 NLP 基准的前提复现不出来。** 任务单称：去掉 `global_look_v1` 白平衡先验并把中灰对齐到 0.25、目标亮度带
   0.48–0.55 后，NLP 11 帧亮度差中位数从 −3.94 L\* 收敛到 −0.97 L\*，ΔE 中位从 9.11 降到 8.63。实测（同一 11 帧，
   对齐 NCC 0.91–0.996）：

   | | ΔE 中位 | ΔE 均值 | dL 中位 | \|dL\| 中位 | 我们 / NLP 的 L\* 中位 |
   |---|---|---|---|---|---|
   | T4c | 9.11 | 11.99 | −0.37 | 1.74 | 54.3 / 57.0 |
   | 只去白平衡先验（wb0，T4c 代码） | 9.07 | 11.85 | −0.26 | 1.74 | 54.3 / 57.0 |
   | 任务单配方（wb0 + 中灰 0.25 + 亮度带 0.48–0.55，T4c 代码） | 9.82 | 11.42 | +2.48 | 3.19 | 57.2 / 57.0 |
   | T4d 标准预设 | 10.00 | 11.41 | +1.96 | 3.00 | 57.3 / 57.0 |

   ΔE 9.11 与任务单一致，但 T4c 在 NLP 上本来就不偏暗（dL 中位 −0.37，均值 +0.47），提亮之后反而比 NLP 亮约 2 L\*，
   ΔE 中位变差（逐帧 6 帧变好、3 帧变差，只有 11 帧）。−3.94 这个起点我测不到；任务单没给计算方法，无法核对差异来源。
   白平衡先验去掉本身对 NLP 几乎没有影响（9.11 → 9.07，1 帧变好 0 帧变差）；对 shop_r01 反而有帮助（7.83 → 7.34，
   7 / 1），185 帧合计 ΔE 中位不变（10.94 → 10.95）。

2. **标准预设按任务单数值实现，没有改。** 185 帧合计略好（ΔE 均值 12.08 → 11.80、91 帧变好 / 68 帧变差、整体亮度
   偏差 −2.37 → +0.36），但中位数略差（10.94 → 11.06），在任务单自己定的对齐目标 NLP 上变差。是否把标准预设的
   亮度带退回 0.45–0.52（T4c 值）请研究方定；我没有在 11 帧上自行调数，避免拿单一来源拟合。
   另外，只做任务单 NLP 配方那三项（T4c 代码上，第 2 节合计表）在 185 帧上比完整标准预设略好（ΔE 中位 10.91 vs 11.06、
   均值 11.74 vs 11.80，ext_own 10.17 vs 10.50）；标准预设多出的几项（反差 1.35、肩部 0.25、饱和度 1.04、矩阵 / 保色 0.40、
   连续逆光权重）把色度比从 0.85 提到 0.92，ΔE 略差。几项同时改，没有逐项拆分，不能归到某一项。

3. **连续逆光权重的触发面大很多。** T4c 硬阈值在 185 帧里触发 21 帧；T4d 标准预设下 66 帧权重 > 0、其中 40 帧权重
   为 1，经典印相 79 帧。去掉"跨度"条件（`backlit_span`）后标准预设为 47 帧，ΔE 几乎不变（第 2 节 `std_nospan` 列）。
   **权重为 1 的帧上五个预设的反差、肩部、中灰都被拉到同一组逆光值**（1.55 / 0.42 / 0.35；任务单把这几个值定为绝对值），
   预设之间只剩曝光、饱和度和色彩差别——`presets_showcase.jpg` 里 A012、A091 和 NLP `_DSF9237` 三行就是这样。
   要不要把逆光目标改成"相对预设"（例如在预设的反差上加一个增量），请研究方定。

4. **切换预设达不到任务单的 < 30 ms。** 46 MP 帧在服务端实测 0.73 s（4×4 估计输入 0.47 s + 估计 0.25 s），浏览器里
   连同刷新约 1 s。估计器本身有多轮二分渲染（约 0.25 s），30 ms 需要重写估计器，没有做。缓存 4×4 估计输入可以降到
   约 0.25 s，这次没改（改了会让评估所用代码与提交不一致），可以另做。

5. **ext_own 的参考图是 `04_已反转成品_对照答案` 文件夹里的成品**（T4c 报告里 dsc6233 按店家扫描对待），不是
   `照片/新疆` 下用户自己的 `-编辑.jpg` 修图；任务单把这一来源称为"你的外景修图"。所以本报告里 ext_own 的 A012 等帧
   的数和 T4c 报告（对用户修图）不能直接比。

6. 6 帧（A016、A018、A025、A026、A027、A028，参考 R052、R058、R085、R089、R092、R096）的参考 JPEG 没有内嵌 ICC，
   没有猜色彩空间，直接剔除；其余 185 帧对齐 NCC 全部 ≥ 0.7（`eval_blueneg.NCC_MIN`）。

## 3. 代码改动（`7f48763`）

- `noref.py` NOREF_V3（rev `t4d-2026-10-24`）：`wb_prior_weight` 0（白平衡证据覆盖不到的部分回退到 temp = tint = 0，
  不再回退到 `global_look_v1`）；`base_midtone` 0.25、`base_contrast` 1.35、`base_shoulder` 0.25、`base_sat` 1.04、
  `target_encoded_band` 0.48–0.55、`chroma_preserve` 0.40、`camera_matrix_mix` 0.40（任务单数值）；
  逆光权重 w = ramp(p90; 0.72, 0.78) × max(ramp(0.36 − p25; 0, 0.06), ramp(p90 − p25 − 0.42; 0, 0.06))，
  肩部 / 反差 / 中灰按 w 向 0.42 / 1.55 / 使 p25 达 0.30 的中灰移动；`STYLE_PRESETS`（5 个，任务单数值）与 `preset_config`。
  `NOREF_V1` / `NOREF_V2` 未改。
- `preview.py`：`Preview.with_auto(cfg)` 在保留的全分辨率正片上重估，不重新解码和反转；导出带 `render_source`。
- `pipeline.convert`：`render_source` → sidecar `render.source`（不影响像素）。
- `app.py`：`/api/open` 接受 `preset`，新增 `POST /api/preset`；meta 给出 `preset`、`presets` 和该预设的
  `camera_matrix_mix`；导出 sidecar 记录预设；`THUMB_REV = "t4d"`。
- `index.html`：右侧面板顶部预设按钮组；中灰滑条 UI 0 = 0.25；相机矩阵 / 保色滑条默认 40。
- 测试：3 个断言因 T4b / T4c 数值变化而更新（反差中心 1.35、上限 `backlit_contrast`、普通场景改为 4 档），新增 5 个。

浏览器核对（dsc6161 A012）：五个按钮切换后滑条、`meta.preset`、按钮高亮一致，token 不变；鲜明 / 经典印相的黑色色阶
显示 −3 / −5；控制台无报错。
