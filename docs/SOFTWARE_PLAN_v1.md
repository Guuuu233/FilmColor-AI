# FilmColor-AI 软件计划 v1：最小可用版本（草案，2026-10-18）

目标：用户能导入负片，看到准实时的正片预览，调整颜色和影调，指定片基，然后导出高质量照片。本地运行，免费开源，暂不处理发布事务。

## 1. 现状审计（2026-10-18，只读）

现在给用户用的入口只有 `scripts/convert.py` 这一个命令行脚本：

- 单帧或多帧相机 RAW / 扫描仪 DNG → 16 位 TIFF（嵌 ICC）+ JSON sidecar；
- 没有 GUI，没有预览，`pyproject.toml` 没有命令行入口（`python -m filmcolor` 不可用）。

| 功能 | 库里已有（src/filmcolor） | 用户能用到吗 | 缺口 |
|---|---|---|---|
| 读入 | 相机 RAW（`rawpy_io.load_raw`，LibRaw 能读的 Bayer / X-Trans）；扫描仪 LinearRaw DNG（`scanner.load_scanner`）；按扩展名和通道数分流 | `convert.py` | **TIFF / JPEG / PNG 负片读不了**（实测 `RawDecodeError`），这是素材库里 568 张 TIFF 彩负、1199 张博物馆 JPEG 用不上的直接原因 |
| 预览 | 无。全程全分辨率，去马赛克约 11 秒 | 无 | 需要“解码一次、渲染很快”的分层 |
| 参数 | `RenderParams`：ev、temp、tint、sat、contrast、midtone、shoulder（`render.py`）；`--auto`（`global_look_v1`）；sidecar 重放（`pipeline.replay_kwargs`） | 只能写 JSON 用 `--render` 传入 | 没有交互调节；`--replay` 不核对输入文件哈希，还会悄悄覆盖其他选项 |
| 片基 | 自动逐帧（`base.estimate_base_auto`）；手动区域（`estimate_base_manual`）；直接给 RGB；整卷（`estimate_base_roll`） | `--base-region T,L,H,W`；整卷要串 3 个研究脚本 | 手动选区靠输入坐标；片基警告只写进 sidecar，用户看不到 |
| 画面区域 | `--image-region`：只影响白点和 QC 统计 | 有 | **输出不裁切、不按 EXIF 旋转** |
| 批量 | `convert.py a b c` 逐个循环 | 有 | 一帧出错，后面全部中止；整卷脚本把路径写死成 `data/raw` |
| 导出 | 16 位 TIFF，自建 v2.1 ICC（按 sRGB 原色解读）；sRGB 或线性编码 | 有 | 不能导出 JPEG / 8 位；不保留 EXIF |
| 黑白 | `--film bw` | 有，需手动指定 | 反转片（正片）不支持 |
| 质量检查 | `qc.quality_checks`：裁切、黑点以下、影调范围等 | 只写进 sidecar | 命令行不提示 warn / fail |
| 测试 | 19 个文件、167 个测试函数；输出哈希只钉死了 1 处（`test_real.py:207`，默认参数） | | auto、bw、扫描仪、自定义参数这几条路径没有钉死哈希 |

另外，冻结保护只在扫描仪路径上按名字拦截（`scanner.load_scanner`）。相机 RAW 路径的保护，靠的是缓存构建脚本里的 `check_source`。研究流程是这样设计的；但用 `convert.py` 直接转换冻结文件不会被拦。这不影响软件功能，只记录在这里。

## 2. 原则

- 复用已验证的引擎：`pipeline.positive` 和 `render`。不重写反转，不改默认输出。
- **默认输出字节不变**：先给现有路径钉死回归哈希，再动代码。
- 未经验证的研究结论不进默认行为：R1 未通过；整卷共享片基只作为“实验性”选项，界面上标明。
- 把不确定性展示给用户：片基警告、裁切比例、片基落在画面内的比例，都直接显示在界面上，而不是藏在 JSON 里。
- 不增加不必要的依赖。

## 3. 界面框架（需要用户决定）

| 方案 | 新增依赖 | 优点 | 缺点 |
|---|---|---|---|
| **A. 本地网页界面（推荐）**：Python 标准库 `http.server` 在本机起服务，界面用一个 HTML 页面加原生 JavaScript，在浏览器里打开 | 只需把 Pillow 从 dev 组移到运行依赖，用来编码 JPEG 预览 | 依赖最少，跨平台；界面和引擎分开，引擎 API 可单独测试；以后容易换成别的外壳 | 不是“原生应用”，需要浏览器；大图传输要靠低分辨率预览 |
| B. Qt（PySide6） | 约 100 MB 的 Qt | 原生窗口，图像控件成熟 | 依赖重，打包复杂，许可是 LGPL |
| C. Tkinter | 无（标准库） | 零依赖 | Homebrew Python 常常不带 Tk；图像显示和交互能力弱 |

## 4. 里程碑

**M0：回归保护（先做，不改行为）**

- 给 4 条路径钉死输出哈希：默认、`--auto`、`--film bw`、扫描仪 DNG。各选一个开发集文件，不用冻结文件。
- 修 `convert.py` 的两处隐患：
  - `--replay` 要核对输入文件的 sha256，不一致时报错；
  - 批量时单帧出错只记录、继续处理下一帧。
- 命令行打印 QC 的 warn / fail 和片基警告。

**M1：预览分层（引擎内部）**

- 新函数：一次性解码、估片基、做反转，缓存一个低分辨率的线性正片，长边约 1500 px，按块平均；渲染时只对这个缓存调用 `render`，目标在 100 ms 量级。
- 预览和导出共用同一套片基、白点、参数。测试要求预览与“全分辨率导出后再缩小”的差异在固定阈值以内。
- 手动片基：`base_regions` 改为接收预览坐标，换算回传感器坐标。

**M2：本地界面，选方案 A 时**

- 打开文件或文件夹，显示缩略图列表；
- 预览区，可对比原始负片和反转结果；
- 7 个参数滑块，加“自动”和“重置”；
- 胶片类型：彩色 / 黑白；
- 片基：自动（默认）/ 在预览上框选区域 / 整卷共享（实验性，默认关闭）。界面显示片基警告、黑点以下比例和高光裁切比例。
- 导出：16 位 TIFF + sidecar；单帧或整卷批量；sidecar 可以重放。
- 测试：服务端 API 单元测试（不需要浏览器）；导出结果与 `convert.py` 逐字节一致。

**M3：之后再做（不在最小可用版本里）**

- 输出裁切和 EXIF 旋转；JPEG 导出；保留 EXIF。
- TIFF / JPEG 负片输入。这类输入不是线性数据，界面上要明确标注“非线性输入，片基估计不可靠”。
- 安装后的命令行入口（`filmcolor`）、README 使用说明。

## 5. 不在本计划里

- 新的 AI 模型；R1 或任何未通过验证的片基规则进入默认行为；发布、许可证、备份。
