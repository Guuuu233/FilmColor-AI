# 确定性反转引擎：信号定义与数学

本文件描述 Sprint 1 引擎每一步的输入、输出、信号含义和色彩空间。代码：`src/filmcolor/raw.py`、`base.py`、`invert.py`。

## 1. RAW 线性化（S1-3，`raw.py`）

| 符号 | 含义 | 色彩空间 / 单位 |
|---|---|---|
| `cfa` | 可见区域的原始传感器值 | DN，单平面 CFA |
| `pattern` | CFA 排列，0=R 1=G 2=B（Bayer 第二个绿合并为 1） | Bayer n=2，X-Trans n=6 |
| `black` | 每个 CFA 位置的黑电平 | DN |
| `linear` | `(cfa - black) / (white - black)` | 相机原生线性 RGB 采样，0=黑电平，1=白电平；无白平衡、无色彩矩阵；读出噪声造成的负值保留 |

两条路径：

- **分析路径**：按 CFA 颜色分别统计（`channel_stats`、`superpixel`），不同颜色的采样从不混合平均。用于片基估计、曝光统计、诊断。
- **渲染路径**：`rawpy_io.demosaic_linear`，LibRaw 全分辨率反马赛克，关闭白平衡、色彩矩阵、自动亮度、`adjust_maximum`；与 `linear` 同一标尺，但低于黑电平的值被截为 0。

两条路径的通道均值差 ≤ 0.8%（12 张全测，`experiments/s1_diag/dual_path.json`）。原因见 `experiments/s1_diag/b_bias_notes.md`：同色不同 CFA 位置的感光不完全相同，不同算法的插值权重不同。**因此片基与画面必须在同一信号上测量**（第 3 节）。

## 2. 片基估计（S1-4，`base.py`）

在分析路径上自动（饱和块排除 → 均匀性筛选 → 最亮候选 → 色度一致性）或手动（多区域）估计，输出采样区域、各通道统计和诊断。

## 3. 密度与反转（S1-5，`invert.py`）

| 步骤 | 定义 | 含义 |
|---|---|---|
| 渲染信号 | `T` (H, W, 3) | 渲染路径线性相机 RGB |
| 片基 | `b = median(T over base regions)` | `base_from_regions`：用第 2 节选出的区域，在**渲染信号**上取中位数 |
| 透射率 | `t = T / b` | 相对片基的透射率，片基处为 1 |
| 密度 | `D = -log10(max(t, 1e-6))` | 片基以上的密度；片基处 0，曝光越多越大；比片基更透的区域为负 |
| 归一化 | `s = (D - D_lo) / (D_hi - D_lo)` | 每通道独立；黑点 `D_lo` 默认 0（片基 = 零曝光），白点 `D_hi` 默认取画面区域内 99.9% 分位 |
| 正片线性值 | `P = (10^(R(s-1)) - 10^-R) / (1 - 10^-R)`，`R = (D_hi,G - D_lo,G) / γ` | 黑点→0，白点→1；`γ` 为胶片 gamma（默认 0.6），决定场景对数范围 R |
| 显示编码 | `O = sRGB_OETF(clip(exposure · P, 0, 1))` | 仅用于观看 |

**模型依据。** 在特性曲线直线段，负片密度 `D_c ≈ γ_c · log10(E / E0)`。对中性灰阶，各通道 `s_c = log(E/E0) / log(E_max/E0)` 与 `γ_c` 无关，因此每通道独立归一化可以消除各层 gamma 差异和色罩，得到中性输出；当 `γ` 等于绿层 gamma 时，`P` 精确还原 `(E - E0) / (E_max - E0)`（`tests/test_invert.py` 验证）。

**假设（可被参数覆盖）：**

1. 片基 = 零曝光，故默认黑点为 0。真实场景的深暗部密度接近片基，会被压到 0（见已知问题）。
2. 画面最亮的高光是中性色，故三通道白点分别取分位数。画面无中性高光时会偏色。
3. 画面区域默认是**居中、各边 50%** 的矩形（`central_region`）：翻拍常含片夹遮罩（极高密度）与片边/背光（低密度），都不能参与白点统计。可手动指定画面区域。`full_image_above_white` 报告全图高于白点的像素比例，比例大说明存在不透光区域或画面区域外有高光。
4. 无串扰模型：真实染料的通道串扰未建模，留给后续校准。

**色彩空间。** `P` 和 `O` 都是**未经色度校准的相机 RGB**（翻拍相机 × 胶片染料），未套用任何色彩矩阵。`O` 只套了 sRGB 传递函数便于观看，原色并不是 sRGB。S1-6 导出时必须如实标注。

### 3a. 扫描仪线性 RGB 输入（S3-1，`scanner.py`）

胶片扫描仪 DNG（主图 `LinearRaw`、3 通道，例如 BlueNeg 的 SilverFast 文件）不经过 CFA 和反马赛克：`T = (v - BlackLevel) / (WhiteLevel - BlackLevel)`，标签缺失时按 DNG 默认取 0 和 `2^bits - 1`。分析路径和渲染路径是同一张图，片基块选择和相机路径共用 `estimate_base_blocks`。红外层只记录统计量，不参与计算。文件里声明的色彩矩阵只是名义标注，`T` 仍按“未校准的设备 RGB”对待。

### 3b. 黑白负片模式（S3-4，`--film bw`，必须显式指定）

`t = cbrt(Π_c max(T_c / b_c, 1e-6))`，复制到三个通道，再以片基 `(1, 1, 1)` 走上表的反转流程。由此得到的密度是三个通道密度的平均，三个通道的白点相同，输出严格中性。假设：银盐密度在光谱上足够平坦，通道之间的差异来自噪声和光源、传感器的不平衡，不是画面内容。`--auto` 时只沿用固定观感里的影调参数（ev、contrast、midtone、shoulder），色温、色调、饱和度和色彩矩阵保持中性，因为固定观感是在彩色负片上拟合的。不做自动识别：默认仍按彩色负片处理。

### 3c. 分块计算（S3-2）

密度、反转和参数化渲染都是逐像素运算，全图按 256 行分块计算；白点分位数和范围报告等全局统计，先在画面区域内的像素上算好，再分块计算。输出和整图计算逐位相同（`tests/test_chunked.py`；真实大图前后 TIFF 逐字节相同，见 `experiments/s3_memory/REPORT.md`）。

## 4. 诊断（`range_report`）

每通道：`clip_high`（画面区域高于输出白的比例）、`below_black`（低于黑点）、`brighter_than_base`（比片基更透）、密度 0.1% / 99.9% 分位；以及 `full_image_above_white`。全部参数由 `InversionParams.to_dict()` 输出，可写入 sidecar。

## 5. 导出（S1-6，`export.py`）

- 16-bit RGB TIFF（zlib 压缩），值 = `round(clip(x, 0, 1) · 65535)`。
- `encoding="srgb"`（默认）：写入第 3 节的 `O`；`encoding="linear"`：写入 `clip(exposure · P, 0, 1)`。
- 嵌入自生成的 ICC v2.1 矩阵/TRC 配置文件：原色取 sRGB（Bradford 适配到 D50 PCS），TRC 为 sRGB 曲线（4096 点）或恒等。描述字段写明 “FilmColor uncalibrated camera RGB - sRGB primaries assumed”。**这是让色彩管理软件能显示的解读方式，不是色度校准结论**；sidecar 中 `colorimetric_calibration = "none"`。
- 不写时间戳，同输入同版本输出逐字节一致。ICC 用 littleCMS（Pillow，仅测试依赖）解析并验证。

## 6. Sidecar 与复现（S1-7，`pipeline.py`）

每个输出 `<stem>.tif` 旁边写 `<stem>.json`（`schema = filmcolor.sidecar/0.1`）：输入路径与 sha256、CFA/黑白电平/crop/元数据；软件版本（filmcolor、git commit、`src` 是否有未提交改动、rawpy、LibRaw、numpy）；解码设置；片基估计（方法、全部区域、统计、诊断、渲染信号上的片基值）；画面区域及来源；反转参数；诊断；输出编码、ICC 描述、输出 sha256。

复现方式：`pipeline.replay_kwargs(sidecar)` 取出片基、白点、画面区域、gamma、曝光、编码，跳过所有估计步骤重放。测试验证两次运行字节一致、重放像素一致。

方向：输出保持传感器方向，不应用 `meta.flip`。

## 7. 异常输入与质量检查（S1-8）

**异常输入**一律报出明确错误，不静默产出：文件不存在 → `FileNotFoundError`；非 RAW、截断、损坏 → `RawDecodeError`（含文件名与 LibRaw 原始错误；RAF 截断即使只缺末尾 100 字节也会被 LibRaw 拒绝，压缩格式未验证）；全饱和、全黑、小于一个块的画面 → 片基自动估计报错并提示手动指定；输入或参数含 NaN/inf、片基非正 → 报错；空白/未曝光画格（画面区域内没有高于黑点的密度）→ 报错并说明可能原因；画面区域越界、参数非法 → 在反马赛克之前报错。位翻转类损坏解码器无法发现，靠 sidecar 中输入 sha256 与样本清单比对。

**质量检查**（`qc.py`，阈值暂定，结果写入 sidecar 的 `qc`）：有限值、取值范围（fail 级）；画面区域编码亮度中位数 0.15～0.85、色调范围 p99−p1 ≥ 0.35、通道均值比 ≤ 1.5、高光裁切 ≤ 0.5%、暗部压黑 ≤ 10%、自动片基块落在画面区域内的比例 ≤ 50%（warn 级）。用于挑出需要人看的图，不评价颜色准确性。

12 张 NLP 样本（`52a4acc`）：11 张 pass，`_DSF9239` 因片基块 100% 落在画面区域内被 warn。核对（画格间隙手动估计）：自动结果取自欠曝暗部，比两侧间隙更透 2～4%，三通道几乎相同 → 片基位置警告属实，但影响约 0.01～0.02 D、近中性。

**已知限制：**

1. **无片边扫描**：片基自动估计只能找到最透的均匀区域。只取画面内部估计时，12 张中 7 张偏差 0.03～0.25 D 且常带通道差异（如 `_DSF9243` 0.05/0.08/0.14 D → 偏色），只有 2 张发出警告。`base_inside_image` 检查能抓到一部分，抓不全。无片边的扫描应手动指定片基，或者在整卷可用时用**整卷片基**（`estimate_base_roll`）：每帧画面内部的最透明区域按快门归一化后，取色度收敛的最低密度簇（S2-5，`experiments/own_roll01/exposure/REPORT.md`）。前提是整卷 ISO、光圈、镜头、光源相同；结果是整卷观察到的最低密度，是片基密度的上界。在 ultramax400_r01 上，逐帧估计有 24/37 帧通道间偏差 > 0.03 D，整卷估计消除了这一项。
2. **无平场校正**：`_DSF9239` 显示画面中心比画格间隙亮 2～4%，可能是照明不均/镜头暗角，也可能是间隙有轻微灰雾，没有平场帧无法区分。照明不均会同时影响片基估计和画面均匀性。自有胶片采集协议（第 9～10 周）应要求每次翻拍拍一张无底片的平场参考帧，并**固定快门**（不用自动曝光），否则快门标称值的舍入（最多 6.7%）和光源强度漂移无法与场景密度区分。
3. **黑点与片基绑定**：管线的黑点固定为片基（`d_lo = 0`）。用整卷片基时，没碰到底的帧（如 3826，最低密度高于底 0.46 D）暗部发灰。`InversionParams.d_lo` 已支持独立黑点，管线尚未暴露；是否作为每帧自动的中性黑点参数，留给无参考优化器（S2-7）决定。
4. **大片均匀雾区的画格**（ultramax400_r01 的 DSC_3858：左侧约 60% 是卷尾未成像但受光的雾区）：白点按画面中心统计，雾区被当成场景主体，输出成棕色中间调（店家与参考拟合都处理成黑色），S1-8 质量检查不报警。S2-7 的 noref_v2 只在输入质量检测里把它标为 `manual_review_required`、不做逐张增强，**反转本身没有修**。判据依赖统计区域：开发实验统计全画面时触发“白点失效”（p99 高出白点 2.06 档），管线只统计中心区域时触发“低信息”（色调范围 2.53 档 < 3）。只有这一个样本，阈值未经独立检验。修正方向（未做）：独立黑点（`d_lo` 取到雾的密度）、检测大片均匀区域、或由用户指定画面区域。
